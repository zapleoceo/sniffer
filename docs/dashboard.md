# Веб-интерфейс владельца

Требование владельца от 31.08.2026. До этого момента ни один процесс SnifferBot
не слушал порт, и это было записано как свойство архитектуры. Требование его
отменяет: появляется пятый процесс с HTTP.

## Что должен показывать

| Раздел | Содержание | Откуда данные |
|---|---|---|
| **Пользователи** | кто пользовался ботом, когда, сколько запросов | `users`, `usage_counters` |
| **Запросы** | лог запросов и переписки: формулировка клиента, собранный паспорт, что ответил бот | `passports`, `passport_events`, новый лог диалога |
| **Расходы** | токены и стоимость по каждому запросу | **AIbroker**, поле `request_id` из ответа задачи |
| **Время** | длительность каждого запроса, где именно оно потрачено | наш замер по этапам плана |
| **Сессия** | состояние сессии юзербота, кнопка переавторизации | `telegram_sessions` |
| **Статистика** | сводка по проекту: источники, находки, доля фолбэков, живость лотов | агрегаты |

## Расходы — как связать наши запросы с брокером

Брокер отдаёт в завершённой задаче поле `request_id` — это идентификатор строки
в его `usage_log`. Его надо сохранять рядом с нашим запросом: без него связать
«клиент спросил про байк» и «потрачено N токенов» можно только по времени, то
есть приблизительно и неверно при параллельных запросах.

Значит: каждый вызов брокера пишет `request_id`, `capability`, `provider`,
`tokens_in`, `tokens_out`, `cost_usd`, `latency_ms` в свою таблицу. Дашборд
показывает наши данные, а не ходит в брокер на каждый просмотр — иначе страница
зависит от доступности чужого сервиса.

## Переавторизация сессии

Сейчас сессия получается командой в терминале. Через интерфейс это выглядит так:
владелец нажимает «переавторизовать», сервис отправляет код, владелец вводит его
в форму, сервис сохраняет новую сессию.

**Осторожно:** это единственное место во всём проекте, где секрет проходит через
HTTP. Строка сессии не должна попадать ни в HTML, ни в логи, ни в историю
браузера; форма принимает только код подтверждения, а сессия сразу уходит
в хранилище зашифрованной.

## Доступ

Интерфейс показывает переписку клиентов и расходы — это не публичная страница.
Вход через Telegram Login Widget с проверкой подписи, доступ только владельцу по
`user_id`. Образец рядом: так сделан дашборд AIbroker.

## Что меняется в инфраструктуре

- Появляется процесс, слушающий порт. `lbot.zapleo.com` перестаёт быть
  зарезервированным именем и начинает обслуживать интерфейс.
- Нужен nginx и TLS — раньше не требовались.
- `docs/deploy.md` в разделе 1 утверждает, что открывать 80/443 не нужно. После
  этой работы утверждение станет неверным и должно быть переписано.
- Healthcheck деплоя сможет наконец ходить по HTTP, а не смотреть на состояние
  контейнеров.

## Уведомления владельцу

Отдельно от интерфейса: бот пишет владельцу (`@zapleosoft`) в личку, когда
происходит то, что требует его вмешательства — в первую очередь **отвалившаяся
сессия юзербота**.

**Важное ограничение Telegram:** бот не может написать первым пользователю,
который не начинал с ним диалог. Владельцу нужно один раз нажать «Старт» у
`@RecVNbot`, после чего его числовой `chat_id` сохраняется в настройках. По
username бот писать не умеет.

Правило для уведомлений: **одно событие — одно сообщение**, с подавлением
повторов. Сервис, который шлёт «сессия отвалилась» каждую минуту, отключают
в первый же день.
