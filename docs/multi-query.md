# Несколько запросов одного клиента

## Пользовательский сценарий

Бот не заставляет человека заранее создавать папки или придумывать названия.
Каждая новая самостоятельная просьба создаёт цепочку паспорта, а короткое имя
для меню берётся из исходной формулировки.

Меню открывается командой `/requests` или кнопкой **«📂 Мои запросы»** под
выдачей. В списке видны все текущие запросы и состояние слежения:

- `🟢` — мониторинг работает;
- `⏸` — мониторинг поставлен на паузу;
- `⌛` — оплаченный период закончился;
- `▫️` — мониторинг не подключён;
- `✓` — активный запрос, к которому относятся следующий ответ и обратная связь.

У одного запроса только четыре понятных действия:

1. **Искать снова** — повторяет поиск с тем же паспортом и не создаёт версию.
2. **Изменить** — просит одну новую полную формулировку; она становится новой
   версией именно выбранной цепочки. Если в ней нет категории, бот задаёт один
   блокирующий вопрос по обычным правилам.
3. **Выключить / включить мониторинг** — ставит доставку на паузу или снимает
   её. Пауза не удаляет историю и не отменяет уже оплаченный период.
4. **Все запросы** — возвращает к списку.

## Инварианты

- `users.active_passport_root` хранит явный выбранный контекст. Выбирать
  «самый свежий паспорт» при нескольких цепочках запрещено.
- `users.editing_passport_root` хранит незавершённое нажатие «Изменить», чтобы
  рестарт процесса между кнопкой и текстом не превратил правку в новый запрос.
- Любой `root` из callback проверяется на принадлежность Telegram-клиенту.
  Чужой или удалённый root не меняет контекст и мониторинг.
- Кнопка оплаты содержит root той выдачи, под которой была показана. Старая
  карточка не может подписать человека на другой, выбранный позже запрос.
- Кнопки уточнения и обратной связи также содержат root своего сообщения:
  нажатие старой кнопки сначала безопасно возвращает нужный контекст.
- Подписка соединяется с текущей версией по корню цепочки. Поэтому правка
  запроса сразу меняет критерии его мониторинга, не создавая вторую подписку.
- Пауза меняет только `subscriptions.is_active`. Матчер читает исключительно
  активные и неистёкшие подписки, поэтому после паузы новые уведомления не
  резервируются.

## Проверка

Обычные диалоговые симуляции запускаются командой:

```bash
uv run python -m sniffer.simulation
```

Многозапросные переходы дополнительно проверяются автоматическими сценариями:
выбор старого запроса после создания нового, повтор без новой версии,
редактирование правильной цепочки, отказ в выборе чужой цепочки, пауза и
возобновление оплаченного мониторинга, состав и размер callback-кнопок.
