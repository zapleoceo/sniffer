# SnifferBot — спецификация v2

> Дополняет [architecture.md](architecture.md). Фиксирует три требования,
> которых в v1 не было: **поиск не ограничен источниками**, **обязательный
> проверяльщик**, **публичный бот с монетизацией**.

## 0. Что меняется против v1

| Требование | Было в v1 | Стало в v2 |
|---|---|---|
| Источники | курируемый список 20–30 чатов, Telethon | агент-планировщик + реестр адаптеров: Telegram, Chotot, веб, опционально FB |
| Границы поиска | заданы списком чатов | заданы **только паспортом запроса**; чем искать — решает агент |
| Проверка выдачи | нет | **verifier** — отдельная ступень и отдельный процесс |
| Аудитория | не определена | публичный бот, задел под монетизацию и антиспам |
| Юзербот | номер не выбран | **отдельный номер**, личный аккаунт не используется |
| Хост | Oracle Free | **Hetzner**, отдельный compose-проект рядом с Верой |

## 1. Изоляция от Веры — контракт

Пересечений нет ни на одном слое. Это проверяемое требование, а не намерение.

| Слой | Вера | SnifferBot |
|---|---|---|
| Репозиторий | `zapleoceo/muai` | `zapleoceo/sniffer` |
| Каталог на сервере | `/var/www/vera3` | `/var/www/sniffer` |
| Compose-проект | `vera3` | `sniffer` |
| Postgres | контейнер `vera3-postgres`, БД `vera` | контейнер `sniffer-postgres`, БД `sniffer` |
| Порт БД на хосте | 5432 | **5433**, только `127.0.0.1` |
| Docker-сеть | `vera3_default` | `sniffer_default` |
| Telegram-аккаунт | личный Димы | **отдельный номер** |
| LLM | AIbroker, ключ проекта `vera` | AIbroker, **свой project-key со своим дневным cap** |

Единственная общая точка — AIbroker. Она безопасна при условии отдельного
project-key: бот физически не может выесть квоту Веры, потому что cap стоит на
ключе. Требование симметричное — Вера так же не может выесть квоту бота.

## 2. Агент поиска — как снимается ограничение по источникам

Формулировка требования: *система ограничена только запросом, что искать, но не
тем, чем искать*. Значит список источников не может быть зашит в код воронки.

### 2.1 Структура

```
паспорт запроса
      │
      ▼
┌─────────────────┐   решает: какие источники, какие запросы, на каком языке
│  search planner │   один LLM-вызов, план по strict json_schema
└────────┬────────┘
         │  план = список задач {source, query, params}
         ▼
┌──────────────────────────────────────────────────────────┐
│  реестр адаптеров — таблица sources в БД, не константы   │
│                                                          │
│  telegram_groups    messages.search по известным чатам   │
│  telegram_discover  resolve_username, поиск новых групп  │
│  chotot             gateway.chotot.com, публичный JSON   │
│  web                SearXNG (ссылки) + Firecrawl (текст) │
│  facebook           выключен по умолчанию, см. 6.3       │
└────────┬─────────────────────────────────────────────────┘
         │  сырые находки
         ▼
   воронка v1: гейт → prefilter → structured → listings
         │
         ▼
   ┌───────────┐
   │ verifier  │  раздел 3
   └───────────┘
```

Добавить источник — это строка в таблице `sources` плюс класс адаптера с одним
методом `search(query, params) -> list[RawItem]`. Планировщик видит доступные
источники из БД и сам решает, какие уместны для этого паспорта. Ни воронка, ни
бот про конкретные источники не знают.

### 2.2 Что решает планировщик

На входе паспорт, на выходе план по строгой схеме:

```json
{
  "tasks": [
    {"source": "telegram_groups", "query": "инжектор", "lang": "ru", "priority": 1},
    {"source": "telegram_groups", "query": "блюкарт", "lang": "ru", "priority": 1},
    {"source": "chotot", "query": "xe ga", "params": {"cg": 2020}, "priority": 1},
    {"source": "web", "query": "Honda Lead cu Nha Trang", "lang": "vi", "priority": 2}
  ],
  "reasoning": "категория motorbike, город nha_trang; вьетнамский сегмент в TG отсутствует, локальный рынок берём с Chotot"
}
```

Планировщик обязан **расширять запрос синонимами, жаргоном и переводами**, а не
брать слова клиента буквально. Обоснование — раздел 7, наблюдение про «инжектор».

Три детали реализации, которые заметны снаружи:

- **`params` в ответе модели приезжают парами строк** `[{key, value}]` и
  разворачиваются в объект при разборе. Strict `json_schema` не допускает
  объект со свободными ключами — провайдеры такое отклоняют.
- **`enum` источников собирается из реестра**, а не пишется в промпт руками.
  Модель физически не может назвать источник, под который нет адаптера.
- **Язык выбирается по источнику, а не по языку клиента.** Русский запрос к
  вьетнамской доске вернёт ноль. Город в текст запроса подставляется только для
  источников, ищущих по всему интернету: в чате Нячанга слово «Нячанг» в
  объявлениях не пишут, и в поисковой строке оно только режет выдачу.

### 2.4 Фолбэк планировщика

Недоступность брокера не должна означать мёртвого бота. При `BrokerError`,
исчерпанном дневном cap, таймауте или невалидном ответе строится
детерминированный план из словаря рынка: предмет на каждом языке источника плюс
глагол сделки, вывернутый по намерению (клиент покупает — ищем «продам», «bán»,
«for sale»).

Фолбэк проходит **ту же нормализацию**, что и ответ модели. Иначе он тихо
разъедется с боевым путём и сломается ровно тогда, когда остаётся единственным
рабочим.

Флаг `is_fallback` — поле плана, а не пометка в тексте: доля фолбэков это
операционная метрика, по ней видно, что брокер лежит.

### 2.3 Бюджет поиска

Свобода источников не означает свободу расходов.

| Параметр | Лимит |
|---|---|
| задач в плане | 12 |
| чатов на один `messages.search` | 10, иначе FloodWait |
| запросов к SearXNG | 5 |
| запросов к Chotot | 5 |
| страниц через Firecrawl | 10 |
| общий таймаут плана | 90 с |
| LLM на запрос | 1 планировщик + 1 на пачку извлечения + 1 на карточку в верификаторе |

Что не уложилось в таймаут — отдаётся частично: пять карточек за минуту
полезнее двадцати за десять.

## 3. Verifier — проверяльщик

Обязательное требование. Ставится между извлечением и выдачей, работает
отдельным процессом, чтобы перезапускаться и версионироваться независимо.

Проверяет три разные вещи, и смешивать их в один вызов нельзя.

### 3.1 Grounding — карточка соответствует исходному тексту

Самый дешёвый и самый важный слой. Модель при извлечении дописывает то, чего в
объявлении нет: «блюкарт есть», когда написано «документы в порядке».

Правило: каждое непустое поле карточки подтверждается подстрокой исходного
сообщения либо явным правилом маппинга.

```
поле карточки → цитата из raw_text → иначе поле обнуляется,
                                     причина not_grounded в лог
```

Для чисел (цена, год, пробег, объём) проверка без LLM — регуляркой по исходному
тексту. Для смысловых полей один дешёвый вызов на пачку.

Провал проверки **не выбрасывает карточку, а опустошает поле**: «год
неизвестен» честнее выдуманного года.

### 3.2 Соответствие паспорту

Цена ошибки несимметрична: показать карбюратор тому, кто просил инжектор, — это
не низкий score, а брак выдачи. Поэтому deal-breaker'ы проверяются отдельно от
ранжирования.

```
must_have отсутствует       → карточка понижается
deal_breaker присутствует   → карточка выбрасывается, причина в лог
поле не определено          → карточка помечается unverified, показывается
                              ниже проверенных и с явной пометкой
```

### 3.3 Живость лота

Главная боль ручного поиска: объявление висит с мая, вещь продана в июне.
Объявления не снимают почти никогда.

| Сигнал | Действие |
|---|---|
| возраст > 14 дней | `stale`, показываем с пометкой «объявление от <дата>, могло быть продано» |
| в треде ответ автора: продано / sold / đã bán | `sold`, скрываем |
| тот же текст переопубликован позже | актуальна последняя публикация, старые схлопываются |
| цена в повторах падает | пишем `price_history`, показываем клиенту динамику |
| сообщение удалено автором | `gone` при следующей проверке |

Живость перепроверяется по расписанию для всех карточек, попавших хоть в одну
выдачу: дешёвый `get_messages` по id, без LLM.

### 3.4 Схема хранения

```sql
listing_verifications (
  listing_id    bigint references listings(id),
  kind          text,   -- grounding | passport_match | liveness
  verdict       text,   -- pass | fail | unknown
  details       jsonb,  -- поле, причина, цитата
  checked_at    timestamptz,
  verifier_ver  text    -- версия правил, чтобы переигрывать на истории
)
```

Карточка без пройденного grounding в выдачу не попадает никогда. Карточка с
`liveness = unknown` попадает, но с пометкой.

## 4. Источники — проверенный статус

| Источник | Статус | Как берём | Ограничения |
|---|---|---|---|
| Telegram, известные чаты | работает, проверено вручную | Telethon `messages.search` | FloodWait; ищет только там, где юзербот состоит |
| Telegram, обнаружение новых | работает, проверено | `resolve_username` по словарю кандидатов | username угадываются; вступление в группу — ручное, с паузами |
| Chotot.vn | **проверен живым запросом, HTTP 200** | `gateway.chotot.com/v1/public/ad-listing`, без ключа и авторизации; Нячанг — `region_v2=7044`, `area_v2=704401`, `cg=2020`, см. 4.1 | недокументирован, может измениться молча; `limit` режется сервером до 50 |
| Веб | SearXNG + Firecrawl, оба self-hosted | SearXNG отдаёт ссылки, Firecrawl — текст страницы | нужно включить формат `json` в SearXNG; +0.8 с на запрос |
| Facebook Marketplace | **выключен по умолчанию** | — | см. 6.3 |

### 4.1 Chotot — проверенные параметры

Снято живыми запросами 29 августа 2026. Справочника регионов у Chotot нет:
`static.chotot.com/storage/chotot-parameters/regions_v2.json` и
`gateway.chotot.com/v1/public/chotot-regions` отдают 404, поэтому коды
восстановлены из самой выдачи — по полям `region_v2` и `region_name`
объявлений, полученных без фильтра по региону.

| Параметр | Значение | Что означает |
|---|---|---|
| `region_v2` | **7044** | провинция Khánh Hòa. Обратная проверка: с этим кодом все 50 объявлений вернулись с `region_name = «Khánh Hòa»` |
| `area_v2` | **704401** | Thành phố Nha Trang. Провинция тянется на сотню километров: Cam Ranh (704402), Ninh Hòa (704405), Diên Khánh (704407) — это уже не Нячанг |
| `cg` | **2020** | категория «Xe máy», мотобайки |
| `limit` | не больше **50** | сервер режет молча: запрос на 1000 вернул 50 объявлений |
| `o` | смещение | постраничный обход, общее число в поле `total` |
| `q` | текст | ищет по `subject` и `body` |
| `st` | `s,k` | шлёт сам сайт; на выдачу для `cg=2020` не влияет |

Нумерация регионов не сплошная: 12000 — Ханой, 13000 — Хошимин, 3017 —
Дананг, а соседние круглые числа пустые. Угадать код нельзя, только снять.

Что реально приезжает в объявлении:

| Поле ответа | Куда идёт в `RawItem` | Оговорка |
|---|---|---|
| `list_id` | `external_id` и ссылка | **не** `ad_id`: значения разные, ссылка строится по `list_id` |
| `subject` / `body` | `title` / `text` | |
| `price` | `price_vnd` | число в донгах; ноль — отсутствие цены, а не цена |
| `price_string` | `price_raw` | «13.000.000 đ» — то, что видит человек |
| `list_time` | `posted_at` | эпоха в **миллисекундах** |
| `date` | никуда | «2 giờ trước», «hôm qua» — фраза по-вьетнамски, не метка времени |
| `images` | `images` | у части объявлений пустой |
| `account_name` | `seller_name` | телефон в тексте Chotot маскирует как `***` |

Ссылка на оригинал — `https://www.chotot.com/{list_id}.htm`: отвечает 200 и
редиректит на канонический адрес с категорийным слагом, который иначе
пришлось бы собирать самим.

Объём рынка на 29 августа: по запросу «байки Кханьхоа» 78 объявлений, из них
60 в самом Нячанге. Это порядок величины, на который рассчитан бюджет
источника — пять запросов на план (2.3) покрывают выдачу целиком.

### 4.2 Почему SearXNG, а не поисковый API

Brave убрал бесплатный тариф для новых пользователей в феврале 2026: вместо
5000 запросов в месяц теперь 5 долларов кредитов, примерно тысяча запросов.
SearXNG self-hosted даёт неограниченные запросы к 70+ движкам за стоимость
своего контейнера и без ключей. При требовании «только бесплатное» это
единственный вариант, который не упрётся в квоту на третьем клиенте.

### 4.3 Зачем Firecrawl рядом с SearXNG

SearXNG возвращает ссылки и сниппеты, но не содержимое. Объявление живёт на
странице, и её надо прочитать. Firecrawl превращает произвольную страницу в
чистый текст или структуру, разворачивается свой инстанс. Без него веб-адаптер
умеет только «нашёл ссылку», что для выдачи бесполезно.

## 5. Публичный бот — антиспам и монетизация

Бот публичный, но тестируется в одиночку. Механика ограничений закладывается
сразу, пороги ставятся щедрыми и правятся конфигом.

### 5.1 Квоты

```
users.tier ∈ (free, paid, owner)

free   3 поиска в сутки · 1 активная подписка · выдача 5 карточек
paid   50 поисков · 10 подписок · выдача 20 карточек · мгновенные уведомления
owner  без лимитов
```

Счётчики в `usage_counters(user_id, day, searches, notifications)`. Проверка
квоты — **до** планировщика, чтобы отказ не стоил ни одного LLM-вызова.

### 5.2 Антиспам

| Защита | Механика |
|---|---|
| Флуд команд | rate-limit 1 запрос в 10 с на пользователя, middleware aiogram |
| Дорогие запросы | поиск стартует только по готовому паспорту, а не на каждое сообщение |
| Абуз LLM | дневной cap на project-key AIbroker — жёсткий потолок расходов |
| Накрутка | капча-вопрос при первом запуске, блок по `user_id` |
| Скам в выдаче | `sellers.scam_score`, жалоба кнопкой на карточке |

### 5.3 Монетизация — что заложить в схему сейчас

Платежи не реализуем, но данные под них закладываем, иначе потом миграция по
живой базе:

```sql
users            tier, tier_expires_at, referred_by
payments         provider, amount, currency, status, external_id, created_at
usage_counters   user_id, day, searches, notifications
```

Кандидат на провайдера — Telegram Stars: не требует юрлица и работает внутри
Telegram. Решение отложено, точка принятия — после первых живых клиентов.

## 6. Риски

### 6.1 Бан юзербота

Отдельный номер снимает риск для личного аккаунта, но не для сервиса. Правила:
только чтение, **ноль исходящих сообщений**, вступление в группы вручную по 2–3
в день, `FloodWaitError` с экспоненциальной паузой, `StringSession` в БД.

Основание: 17 августа 2026 личный аккаунт поймал `PEER_FLOOD` после пяти
сообщений незнакомым людям подряд. Отправка отбилась, лимит снимается часами.
Для сервиса, который живёт на одном аккаунте, это означает простой — поэтому
исходящих действий у юзербота не должно быть вообще.

### 6.2 Chotot меняет API

API недокументирован. Защита: адаптер изолирован, при ошибке парсинга источник
помечается `degraded` и исключается из планов до ручной починки. Клиент этого
не замечает — получает выдачу из остальных источников.

### 6.3 Facebook Marketplace — почему выключен

Meta запретила автоматический сбор данных в ToS с 1 января 2025 независимо от
того, залогинен ли сборщик. Разлогиненный поиск заблокирован технически,
известные краулеры в чёрном списке, аккаунты за скрейпинг банят.

Адаптер в реестре предусмотрен, `enabled = false`. Включение — осознанное
решение владельца с пониманием, что это нарушение ToS и риск бана аккаунта.
Технически потребует отдельный аккаунт и резидентные прокси, то есть деньги, а
не бесплатно.

## 7. Полевые уроки — откуда взялись требования

Выведено из ручного поиска скутера в Нячанге 14–17 августа 2026: 25
просмотренных чатов, около 40 найденных объявлений, три диалога с продавцами.
Это не гипотезы.

| Наблюдение | Следствие для продукта |
|---|---|
| «скутер» не находил половину лотов, а «инжектор» и «блюкарт» находили | планировщик обязан расширять запрос синонимами и жаргоном рынка |
| одно объявление лежит в пяти группах | дедуп по нормализованному тексту обязателен, иначе выдача из копий |
| майские объявления висят как живые | verifier, раздел 3.3 |
| цена в повторах падала 25 → 24 → 23 → 22 | `price_history` — сигнал «продавец готов торговаться» |
| «документы в порядке» ≠ блюкарт на продавце | grounding: не превращать расплывчатое в конкретное |
| «двигатель в отличном состоянии» при чеке о расточке неделю назад | оценки продавца не факт; чеки и фото — отдельная ценность, их надо извлекать |
| вьетнамцы в Telegram байки не продают вообще | без Chotot теряется весь локальный рынок и 10–20% разницы в цене |
| `search_dialogs` стабильно отваливается по таймауту | использовать `resolve_username` + `search_messages`, не перебор диалогов |
| API не отдаёт username автора поста в группе | контакт берём только из текста объявления, иначе отдаём ссылку на пост |

## 8. Этапы

| Этап | Содержание | Критерий готовности |
|---|---|---|
| **P0** | диалог → паспорт → планировщик → 2 источника (telegram_groups, chotot) → 5 карточек | выдача полезна на реальном запросе про байк |
| **P1** | ингест, воронка, Postgres, verifier grounding + liveness | карточки не врут, мёртвые помечены |
| **P2** | SearXNG + Firecrawl, telegram_discover, подписки, outbox | источники расширяются без правки кода |
| **P3** | квоты, tier, платежи, скам-скоринг, второй город | бот выдерживает чужих пользователей |

Точка принятия решения между P0 и P1 не техническая: вопрос в том, попадает ли
выдача в запрос. Если карточки мусорные, остальное бессмысленно.
