# Read-only прототип двух агентов: конечный цикл инструментов

`agents/` — изолированный прототип, ещё не подключённый к рабочему боту,
коллектору или планировщику. Он не создаёт задания и не меняет БД. Write-tools
не допускаются до появления журнала действий и leases заданий.

Модель вызывается только через `BrokerModel` → AIbroker `chat()` с нативными
`tools`, `tool_choice=auto`, capability `chat:sales`. Нет прямых SDK провайдеров,
разбора JSON из обычного текста, исправления аргументов или скрытых повторов.
Вызов инструментов требует явного `finish_reason=tool_calls`; финальный текст —
`stop`. Старый брокер без метаданных завершения для **этого** цикла непригоден:
runtime отказывает безопасно, а не угадывает действие.

`McpReadTools` адаптирует уже подключённую/аутентифицированную MCP ClientSession
через протокол `call_tool`. Это настоящий интерфейс MCP-вызова, но не запущенный
MCP-сервер и не готовая транспортная конфигурация. Принимается только
`structuredContent`, `isError` запрещает использование ответа. Текстовые
блоки MCP не преобразуются в команды или JSON.

Имена и обе схемы инструментов задаются доверенным приложением. Отдельный
allowlist ограничивает доступ у runtime и MCP-адаптера; discovery, описания
инструментов и `readOnlyHint` не расширяют права. В production сервер также
обязан проверять авторизацию: локальный allowlist не заменяет её.

Перед **первым** вызовом инструмента проверяется весь пакет текущего хода:
причина завершения, refusal, уникальные ID (также между ходами), известные имена,
размер аргументов, корректность JSON и входные схемы. Ошибка в последнем вызове
пакета означает ноль выполненных вызовов этого пакета. Результат каждого MCP
вызова проверяется по выходной схеме перед передачей модели.

По умолчанию: 3 хода модели, максимум 4 вызова инструментов, общий deadline
20 секунд, запрос и аргументы по 8000 символов, результат инструмента и текст
модели по 16000. Лимиты конечны/положительны, целочисленные счётчики не принимают
bool/float. На последнем ходе новые инструменты не выполняются: результата уже
не успеет прочитать модель. Копии схем и истории защищают runtime от мутаций
внедрённого адаптера. Отмена вызывающей задачи не подавляется.

`tests/test_agent_runtime.py` — офлайн-симуляции доверенного брокерного контракта,
MCP-сессии, негативных пакетов и ограничений. Они не доказывают доступность
native tool calling в развернутом AIbroker: это отдельный интеграционный gate
перед подключением к production. Финальный текст также требует продуктовой
проверки фактов; валидные инструменты сами по себе не доказывают правдивость
свободного ответа модели.
