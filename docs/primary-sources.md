# Первоисточники и дедуп объявлений

Решение владельца от 16.11.2026: карточка ведёт на **первоисточник** — пост в
том чате или канале, где объявление опубликовано впервые, — и одно объявление
даёт **одну** карточку, сколько бы копий ни пришло.

## Что считается копией

| Вид | Как узнаём | Что делаем |
|---|---|---|
| Пересылка с адресом | `fwd_from`: канал + `channel_post` (или `saved_from_peer` + `saved_from_msg_id`) | ссылка — на пост канала `t.me/<канал>/<номер>` |
| Пересылка без адреса | `fwd_from` есть, адреса поста нет (от человека, скрытый автор, группа) | **не первоисточник**: карточки нет, в живом поиске не находка |
| Указатель | текст — по сути одна ссылка на чужой пост, сокращатель или внешний сайт (остаток короче 25 букв/цифр) | ссылка на пост Telegram → это и есть оригинал; сокращатель/сайт → первоисточник **не определён** |
| Кросспост / перепост | тот же текст (отпечаток `domain/fingerprint.py`) в другом чате или с новым номером | одна карточка, ссылка — на самую раннюю копию |
| Перепост с новой ценой | тот же текст без цены (`domain/listing_identity.py`) в том же городе, категории и стороне сделки | одна карточка, цена — самая свежая |

Имя канала-оригинала берётся из сущностей ответа Telegram (без лишнего запроса),
а если его там нет — из реестра `chats`. Ссылку `t.me/c/…` клиент открыть не
может, поэтому без имени канала первоисточник не выдаётся. Сокращатели мы не
раскрываем: сборщику запрещено ходить по произвольным адресам.

Ссылки на карту (`maps.app.goo.gl`, `google.*/maps`), на автора (`t.me/имя` без
номера поста, `@имя`) и цены с точками («8.500.000đ/tháng») указателем не
считаются. Сухой прогон на живой базе 16.11.2026: из 31 997 активных карточек
архива указателем не признана ни одна.

## Где это работает

- **Коллектор** (`collector/ingest.py`) пишет в `raw_messages` первоисточник:
  `origin_kind` (`NULL` — сообщение само оригинал, `forward`, `forward_hidden`,
  `pointer`), `origin_chat_tg_id`, `origin_msg_id`, `origin_username` и
  `identity_hash` — отпечаток без цены. Миграция `026_primary_sources.sql`.
- **Воронка архива** (`worker/archive.py`): копия без первоисточника уходит в
  `rejected` с причиной `not_primary`. Дубль (по отпечатку или, при совпадении
  города/категории/стороны, по отпечатку без цены) не создаёт карточку:
  `pipeline/duplicates.py` оставляет карточку на самом раннем публичном посте и
  переносит в неё только цену и `posted_at` свежей копии; копия — `duplicate`.
  Раньше свежий перепост забирал карточку целиком, со ссылкой.
- **Живой поиск Telegram** (`sources/telegram_mapping.py`): пересылка ведёт на
  оригинал, копия без первоисточника находкой не считается.
- **Проверенный каталог** (`agent_app/collector_gateway.py`,
  `db/repositories/catalog_observations.py`): архив отдаёт только первоисточники
  (SQL отсекает `forward_hidden` и `pointer`), ссылка пересылки — на оригинал.
  Копии внутри одного задания отбрасываются до извлечения (`duplicates_skipped`).
  Копия уже опубликованного объявления (общий ключ личности: ссылка на
  первоисточник, отпечаток текста, отпечаток без цены) не пишется ни в
  наблюдения, ни в публикации — `catalog_stage` отвечает `duplicate_of`.
  Публикации хранят `identity_keys`; помеченные `duplicate_of_*` в выдачу не идут.

## Уборка базы — `python -m sniffer.worker.primary_cleanup`

По умолчанию — **сухой прогон**: печатает JSON с числами и до 10 примеров
«до/после», ничего не пишет. `--apply` исполняет план короткими транзакциями;
повтор находит пустой план. `--near` добавляет слияние перепостов с новой ценой.

1. **Карточка на поздней копии** (`earlier_copy`): прежний вход отдавал карточку
   свежему перепосту. Если в сырье есть более ранняя копия того же текста в чате с
   публичным именем — карточка переезжает на неё (ссылка, `raw_message_id`,
   `external_id`); цена и дата остаются.
2. **Указатели**: ссылка → на оригинал; у оригинала своя карточка → указатель
   гасится как дубль; оригинал не определить → гасится как `not_primary`.
3. **Дубли**: группа (город, категория, сторона сделки, ключ) → остаётся самая
   ранняя публичная карточка, цена — самая свежая, остальные гасятся с причиной
   `duplicate_merged`.
4. **Проверенный каталог**: публикациям проставляются `identity_keys`, копии
   помечаются `duplicate_of_*`.

Ничего не удаляется. Снимок «как было» каждой изменённой карточки пишется в
`listing_cleanup_events` (только добавление) — по нему уборку можно откатить.

### Сухой прогон на живой базе, 16.11.2026

Выполнен только на чтение (`SET TRANSACTION READ ONLY`, одноразовый контейнер).

| Что | Сколько |
|---|---|
| активных карточек архива просмотрено | 31 996 |
| карточек на поздней копии при живой ранней (`earlier_copy`) | 7 533 к переезду, из них 2 318 — ранняя копия в том же чате; ещё 354 не переносятся: у ранней копии уже есть своя (погашенная) карточка |
| указателей / без первоисточника / неканонических ссылок | 0 / 0 / 0 |
| групп точных дублей (тот же текст) среди активных | 0 |
| групп перепостов с новой ценой (`--near`) | 788 групп, 1 232 карточки к погашению, около 730 смен цены |
| публикаций проверенного каталога / дублей среди них | 10 / 0 |

Точных дублей среди активных нет потому, что вход и раньше схлопывал одинаковый
текст; зато он отдавал карточку последней копии — отсюда 7 533 переезда.

### Что решает владелец

- **Запуск `--apply` на production** — не выполнялся.
- **`--near`**: перепост с новой ценой сливается только по совпадению всего
  текста, кроме цены. Среди примеров есть пары с заметной разницей цены
  (45 → 30 млн): это может быть снижение цены, а может — соседняя квартира с
  тем же описанием. Без `--near` эти 788 групп остаются как есть.
- **Ранняя копия в том же чате** (2 318 из 7 533): продавец мог удалить старый
  пост и выложить заново. Тогда ссылка на ранний пост мёртвая; проверка живости
  погасит такую карточку, и следующий перепост создаст новую.
