# Вкладки поиска: карточка фильтра, панель «Мои слежения», темы Telegram

Источники решений: R1 §9.4–9.5 и WP-11, R6 фазы 1–2 (`scratchpad/review/product`), решения владельца
03–04.10.2026: темы Telegram (Threaded mode) включаем, панель «Мои слежения» идёт первой, Mini App
позже, «Удалить поиск» = пауза и архив. Деньги и квота — `docs/monetization.md`.

## Фаза 1. Работает во всех клиентах, темы не нужны

### Реестр полей (`domain/field_spec.py`)

Один реестр на знание «какие бывают условия поиска». По нему рисуются чипы и по нему же
`domain/passport_edit.py` проверяет правку. Список атрибутов по категориям не дублируется:
категории поля берутся из `CATEGORY_ATTRIBUTES` (`_owners`), а `tests/test_field_spec.py` падает,
если у атрибута паспорта нет поля.

У каждого поля признак `monitor` — правда о том, как поле читает монитор слежения
(`matching/rules.py`, таблица R6 §3.6): `yes` сужает, `partial` — только равенство при известном
значении лота, `no` — не читает вовсе. Карточка пишет «слежение это условие не учитывает» у полей с
`no` (районы, обязательно, исключить, бюджет от): иначе человек правит район и ждёт эффекта, которого
нет. Город — `required`: без него монитор не работает вовсе, снять его нельзя.

### Правка (`domain/passport_edit.py`, `db/repositories/passport_edit.py`)

`apply_changes(passport, changes)` — чистая функция: проверка по виду поля (выбор из вариантов, да/нет,
положительное число, список слов, текст), операция «снять поле» (`Change(key)` без значения; `merge_edit`
снимать не умел). Набор применяется целиком или не применяется вовсе. `raw_query` правка не трогает.
Снятие `engine_cc` уносит и `engine_cc_dir`.

`PassportEditor.edit(user_id, root, base_version, changes)` пишет ОДНУ новую версию и событие
`manual_edit` (`{"set": {...}, "removed": [...]}`). Номер версии, на которую смотрел человек, едет в
кнопке; при расхождении под блокировкой корня — `StaleVersion`, карточка перерисовывается свежей с
пометкой. Слой для Mini App тот же (`webapp → domain, db`).

После правки поиска со слежением карточка добавляет строку: монитор уже просмотрел часть объявлений и к
ним не вернётся, расширенный фильтр поймает только новые (курсоры `since_listing_id` /
`scan_listing_id` не сбрасываются, R6 §3.6).

### Карточка фильтра (`bot/filter_card.py`, `bot/filter_flow.py`, `bot/handlers/watch.py`)

Одно сообщение, правится на месте. Чипы: `✎ Поле: значение` открывает поле, `✕` снимает. Поля с
конечным выбором (коробка, состояние, документы, двигатель, флаги жилья) правятся кнопками значений и
«любое»; числа, города, марки, списки — приглашением написать значение сообщением (тот же путь, что у
«✏️ Изменить»: `users.editing_passport_root`). «＋ условие» — выбор из ещё не заданных полей.
Провод: `flt:<корень>:<версия>:<поле>:<действие>:<вариант>`, ≤ 64 байт (тест).

### Панель «Мои слежения» (`bot/watch_panel.py`, `bot/watch_flow.py`, `db/repositories/watch.py`)

Команда `/watch` и кнопки `wch:*`. Показывает: слоты (куплено — число живых подписок
`BillingRepository.live_subscriptions`; занято — привязанных к поискам строк `subscriptions`), поиски
со статусами (🟢 слежу, ⏸ пауза, ⌛ закончилось, ▫️ нет) и предел поисков.

- **Предел поисков**: `plans.FREE_SEARCHES = 5`, `plans.PAID_SEARCHES = 10` (`search_cap(slots)`).
  Считаются не убранные поиски. Предел применяется при открытии нового поиска из панели (и при
  создании вкладки, фаза 2); путь `/new` в чате остаётся прежним (вытеснение из списка, `domain/threads.py`).
- **Пауза / возобновление** — `DeliveryRepository.set_active`, как и раньше.
- **Перенос слота** — смена корня у той же строки `subscriptions`: срок и `charge_id` (ключ отмены) не
  меняются, курсоры просмотра ставятся на «сейчас», карантин сбрасывается. Цель — свой поиск без живого
  слота; просроченная строка на цели снимается (она занимала уникальный ключ).
- **«Удалить поиск»** — с подтверждением: слежение на паузу, поиск получает строку `search_tabs` со
  статусом `archived` и исчезает из списков, из «текущего» поиска и из цели кнопок. Версии паспорта
  остаются. Оплаченный слот остаётся за клиентом до конца срока и переносится на другой поиск.

Чего панель НЕ делает: не включает слежение свободным слотом без платежа. Привязка нового слота к
поиску — часть оплаты (`pay_and_activate`, пакет слотов Stars), здесь её нет.

### Схема

`infra/sql/015_search_tabs.sql` — таблица `search_tabs(user_id, passport_root, message_thread_id,
shown_title, state, created_at)`, `UNIQUE (user_id, passport_root)`, `UNIQUE (user_id, message_thread_id)`,
`state IN ('open','lost','archived')`. Корень без внешнего ключа (как `subscriptions.passport_root`).
Только DDL, ALTER существующих таблиц нет, часовой в `deploy.sh` не нужен. ORM-зеркало —
`db/models/tabs.py`.
