# Закрытый MCP главного агента

Сервер MCP создаётся внутри процесса для одной доверенной `MainIdentity`:
внутренний `users.id`, корень и версия запроса. Он не слушает TCP-порт,
не публикуется наружу и проходит настоящий handshake/list/call транспорта MCP
через память. Идентификатор клиента, запрос, город и бюджет отсутствуют в
аргументах модели; репозиторий повторно проверяет владельца, актуальность версии
и подставляет фильтры сам.

Модель вызывается только `BrokerModel` через AIbroker. Ей доступны два read-only
инструмента: поиск в свежем проверенном каталоге и состояние покрытия. Ответ
модели не становится карточкой: приложение повторно читает проверенные строки,
создаёт `RawItem` и применяет детерминированное ранжирование. При ошибке брокера
прямого provider fallback и live-поиска нет.

Постановка задания выполняется приложением, а не произвольным tool call модели:
только для текущей версии, при устаревшем/неизвестном покрытии, не более одного
pending/running задания. Shadow не создаёт заданий. Отключённый сборщик честно
отображается отключённым. Для USD без доступного курса результат не объявляется
подходящим бюджету.

Схемы MCP запрещают лишние поля. Неизвестные tools, `user_id`, SQL, произвольные
URL и расширение лимитов отклоняются до вызова gateway. Исключения превращаются
в безопасный `tool_rejected` без исходного текста и диагностики БД.

Реализация использует MCP Python SDK `>=1.28,<2`: сознательно зафиксирована
поддерживаемая ветка 1.x, API которой применяется в сервере и тестах. Переход на
SDK 2.x — отдельная миграция с повторной проверкой транспорта.
