# SnifferBot: публичный каталог через MCP

В личном чате бот отвечает ссылкой. `/start` и `/mcp` дают один и тот же адрес:

```
https://lbot.zapleo.com/mcp/catalog
```

Добавьте его в клиент, который поддерживает удалённые MCP-серверы без
авторизации, транспорт Streamable HTTP. Это адрес сервера, не веб-страница
и не ключ. Отдельный аккаунт и оплата не нужны. Примеры запросов: «покажи
квартиры в Нячанге до 6 млн донгов в месяц», «найди Honda Vision на продажу».
Не все клиенты позволяют добавлять произвольные удалённые MCP-серверы.

| Инструмент | Что делает |
|---|---|
| `catalog_guide` | Справочник городов, районов, категорий, видов сделки и источников |
| `browse_listings` | Просмотр каталога без фильтра |
| `search_listings` | Фильтры города, района, категории, сделки, источника, бюджета VND, периода цены и свойств |
| `get_listing` | Одна карточка по ID со ссылкой и признаком происхождения |

После каждой страницы повторите запрос с прежними фильтрами и
`before_id` из `next_before_id`. До 50 результатов на запрос, без общего
потолка страниц; новые записи не сдвигают страницы с уже выданным курсором.
Неизвестные свойства возвращаются как `null`; при явном фильтре на свойство
совпадением считается только известное значение. Код справочника моделей
берётся из общего справочника SnifferBot. Валюта и период цены не угадываются.

Каталог отдаёт активные предложения из общедоступных источников.
Telegram: карточку связываем с текущей активной записью публичного сообщества
и конкретным сообщением; у пересылки проверяем также известный общедоступный
первоисточник. Chợ Tốt: только штатный URL числового объявления.

`source_evidence` поясняет, что установлено: `marketplace_post` — карточка на
площадке; `telegram_forward_origin` — адрес исходного поста, сохранённый
Telegram; `telegram_observed` — публичный пост, который увидел сборщик, но
который может оказаться ручным перепостом. `source_reference_only: true` в
`search_listings` исключает последнюю категорию. Это проверка происхождения
ссылки, а не подтверждение, что её разместил собственник или что предложение
всё ещё доступно. В карточке
только структурированные рыночные факты и ссылка. Сырой текст, произвольные
поля, контактные данные, авторы, медиа и приватные URL не возвращаются.
Внутренний агентский MCP, поиск по сырью и кабинет владельца не открываются.
Ограничения размера запроса, конкуренции и времени SQL защищают общий сервис.

Платные подписки и новые счета клиентам не оформляются. Старые экранные кнопки не
активируют старый поток. `/paysupport` остаётся для ранее проведённых платежей.
Состояние существующих платных обязательств проверяется деплоем до
переключения. Если журнал платных периодов / продлений не читается или
содержит неразрешённые обязательства, переключение отменяется без изменения
платежей. Действующий внутренний монитор владельца остаётся; состояние
старых клиентских задач не удаляется. Коллектор, обработка, таблицы каталога
и кабинет владельца остаются на той же базе. Откат — штатный Git revert.
Процедура переключения рассчитана на существующую базу. Если базы или таблиц
журнала нет, автоматический релиз остановится до замены сервисов. Для новой
инсталляции сначала подготовьте схему штатным способом, не трактуйте ошибку
чтения как отсутствие платных обязательств.

## Бесплатные рассылки через личный MCP

Массовый публичный каталог остаётся анонимным и только для чтения. В личном
чате с ботом команда `/mcp` также выдаёт адрес персонального Streamable HTTP
сервера `https://lbot.zapleo.com/mcp/personal` и приватный ключ для заголовка
`Authorization: Bearer …`. Ключ вводится в настройку заголовков MCP-клиента,
а не в промпт, URL или параметры инструмента. Нужен клиент, поддерживающий
пользовательские HTTP-заголовки: публичный каталог работает и без них, но
OAuth-only клиенты не подключат персональную рассылку этим способом.
Запрос нового ключа заменяет предыдущий, не удаляя активные рассылки.

У персонального сервера остаются обычные инструменты каталога и добавляются:

| Инструмент | Что делает |
|---|---|
| `create_watch` | Сохраняет фильтры новых объявлений; обязательны город, категория и сделка |
| `list_watches` | Показывает только собственные активные рассылки |
| `stop_watch` | Останавливает собственную рассылку по ID |

Опциональное поле `districts` принимает список районов из `catalog_guide`
вместо одного `district`. Десять активных рассылок на аккаунт; повтор
одинаковых фильтров не создаёт дубль. Уже опубликованные объявления при
создании не шлются. Получатель всегда тот, кому бот выдал ключ в личном
чате: API не принимает Telegram ID от клиента. Нотифаер отправляет новые
совпадения с короткими рыночными фактами и ссылкой, не перепечатывая объявление. В рассылку попадает только карточка площадки
или подтверждённая в данных пересылки ссылка на исходный пост Telegram.
Это подтверждает ссылку, но не право собственности автора.
Ссылка, уже доставленная этому Telegram-аккаунту, не шлётся повторно даже
при пересечении двух рассылок. Успешная обычная отправка фиксируется в БД;
после сетевого сбоя с неопределённым результатом Telegram не предоставляет
ключа идемпотентности, поэтому рассылка может повторить сообщение при ретрае.

Старые платные подписки, счета и платежи не переактивируются. У публичного
каталога и сборщиков нет зависимости от состояния личных рассылок.
