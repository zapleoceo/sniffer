# Нативные инструменты: транспорт SnifferBot → AIbroker

`BrokerClient.chat` принимает необязательные `tools` и `tool_choice` и передаёт
их через существующую очередь `/v1/jobs`. По умолчанию при наличии tools выбор
равен `auto`; без tools новые поля отсутствуют, старый текстовый контракт не
меняется. Пустой список инструментов, выбор без инструментов и одновременный
`response_format` отвергаются до HTTP-запроса.

Ответ `BrokerResult` сохраняет `tool_calls`, `finish_reason` и признак refusal.
Пустой текст при наличии tool calls допустим. История assistant/tool вместе
с `tool_call_id` передаётся без перекодирования в текстовый промпт. Учёт расходов
остаётся тем же внедряемым приёмником: один завершённый вызов — одна запись.

Клиент — транспорт, он **не исполняет** инструменты. Проверка схем аргументов,
авторизация инструмента и ограничения цикла обязательны на стороне исполнителя;
ответ брокера сам по себе не разрешение менять БД. Отсутствующие метаданные
старого брокера не преобразуются в выдуманный tool call.

Нужна брокерная ветка `codex/sniffer-native-tools`. До её интеграционной проверки
и выкладки production-вызовы tools не включать. Тесты `test_broker_tools.py`
проверяют HTTP-контракт с заглушкой брокера, не совместимость живых моделей.
