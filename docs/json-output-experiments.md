# JSON: проверенные варианты через AIbroker

Дата: 2026-09-03. Изменения только в ветках миграции, не выложены в production.
Все живые вызовы выполнены через очередь AIbroker, capability `chat:sales`;
прямых обращений к провайдерам, увеличения дневного лимита и смены моделей вручную нет.

## Диагноз

В исходном замере за 48 часов: 131 попытка проекта sniffer-bot, 113 успешных,
3 InvalidJSON. Все три ошибки listing_guard были на Gemini 2.5 Flash Lite:
12 карточек, лимит 896 токенов, фактический вывод около 882–884.
Остальные попытки не следует считать JSON-ошибками.
Одна лишь смена capability на sales не устранила проблему: повтор исходной
задачи 458687 с теми же 896 токенами (job 460439) снова дал InvalidJSON
на Gemini 2.5 Flash. В наблюдавшемся окне задача не завершилась; это не
доказательство успешного fallback и не проверка текущего статуса задачи.

лимит на 2048. Вариант B оставляет 896, но убирает `why` из схемы и инструкции.

## Выбранное изменение

Сохраняем `why` для диагностики и задаём `128 × число карточек + 512`
токенов: 2048 для стандартной пачки 12. Для коротких пачек лимит меньше;
живой прогон выше относится только к пачкам по 12.
Число вызовов, sales-маршрут, схема и таймаут 20 секунд не меняются.
Лимит — максимум генерации, не фиксированная оплаченная сумма.

Другие варианты:

- Компактная схема: проверена выше, резервный вариант; теряет объяснение.
- Деление пачки: может снизить риск обрыва, но увеличивает число запросов и
  задержку. Живой прогон не проводился, автоматически не включено.
- Строгая локальная JSON Schema-валидация: отдельный слой клиента отвергает
  обрывы, отказ, неверные типы, лишние поля, дубли ключей и нечисловые значения.
  Проверяется офлайн отрицательными тестами. Она обнаруживает ошибку,
  а не заставляет модель всегда генерировать правильно.
- Нативные tool calls через брокер: основа новой архитектуры. Аргументы всё
  равно проверяются схемой до вызова инструмента. До выкладки брокерной ветки
  возможна лишь контрактная офлайн-проверка; live-поддержка не заявляется.
- «Починить JSON» регулярками или оплаченной второй генерацией: не включено,
  потому что легко изменить смысл, скрыть обрыв или незаметно удвоить расход.

Текущий охранник остаётся необязательным улучшением: при BrokerError/таймауте
работает старый fallback с непроверенной выдачей. Это **не** fail-closed
политика нового агента. У нового агента невалидный вызов инструмента должен
давать ноль вызовов инструментов этого шага; подключение записи в БД
допускается только после журнала действий и проверки полномочий.
