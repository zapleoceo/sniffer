# Граница ответа AIbroker

Все вызовы моделей остаются через AIbroker: submit `/v1/jobs`, затем polling.

## Terra первой, прежняя схема запасной

Production Compose включает `BROKER_PRIMARY_MODEL=codex-sub/gpt-6.1-terra` перед
каждым `BrokerClient.chat()` / `structured()`. Точный ID, subscription billing,
`available=true`, structured и tools проверены 16.11.2026 через `/v1/models`
с действующим ключом проекта Sniffer. Аккаунт выбирает Broker по действующей
политике проекта; клиент не задаёт аккаунт и не расширяет доступ.

Первая попытка ограничена `BROKER_PRIMARY_TIMEOUT_S` (30 секунд, включая submit).
Это одно задание с уникальным `Idempotency-Key`, без повторной отправки. При
известном job_id и потере связи/тайм-ауте клиент запрашивает отмену и до
`BROKER_PRIMARY_CANCEL_TIMEOUT_S` (5 секунд) ждёт терминального состояния.
Одного `cancel_requested` недостаточно. Неопределённый submit, неподтверждённая
отмена, отказ доступа и исчерпанный бюджет завершают вызов ошибкой, без платного
fallback. Ключ, промпт и текст модели в диагностике маршрута не печатаются.

При явном отказе модели, пустом/неполном ответе или негодном JSON запускается
ровно прежняя схема: intake/offer_screen — `gemini/gemini-3.5-flash-lite`, затем
один старый unpinned fallback; остальные роли — их прежняя настройка
`BROKER_MODEL_*` или цепочка по capability. Негодный ответ этой цепочки не
запускает Terra заново. Все прежние max_tokens/temperature сохраняются для
fallback. Подписочный контракт их не передаёт модели, поэтому первая попытка
не отправляет эти параметры; ограничение времени не является лимитом токенов.
Ответ Terra принимается только с subscription billing и ожидаемыми provider/model.
Учёт завершённых ответов сохраняется, включая отклонённые локальной валидацией.

Без client tools передаётся `no_shell=true`; с tools остаётся проверенный Broker
client-tool протокол и авторизация инструментов Sniffer. Транскрипция и отдельный
процесс agent-collector с его собственным agent-run API не перенастраиваются.
Прямой запуск Python по умолчанию сохраняет старый маршрут. В Compose явное
`BROKER_PRIMARY_MODEL=` отключает префикс; параметры остальных ролей не меняются.

`tests/test_broker_primary.py` проверяет HTTP-контракт без живых моделей:
успех, прежние fallback, недопустимый ответ, бюджет/доступ, неопределённую отправку
и подтверждение отмены до следующего задания. Live inference не является частью
этих тестов; production-маршрут проверяется по существующим заданиям и логам.

## Проверка ответа

`BrokerClient.structured()` отправляет `json_schema` со `strict: true`, но не
считает это гарантией: провайдер может обрезать ответ или отказаться отвечать.

Перед платным вызовом проверяется корректность самой JSON Schema. После ответа
клиент принимает только JSON-объект, соответствующий схеме (тип, enum, required,
additionalProperties и вложенные ограничения — через `jsonschema`). Повторяющиеся
ключи, NaN/Infinity, переполнение чисел, Markdown-обёртки и хвост после JSON
отклоняются. Никакого автоматического «ремонта» JSON или повторной покупки ответа.

Если брокер передал `refusal`, ответ отклоняется. Если передал `finish_reason`,
принимаются только `stop` (без учёта регистра), `end_turn`, `completed`;
обрезание, фильтрация и неизвестные причины считаются незавершённым ответом.
Старый брокер без этого поля поддерживается, но в таком случае отличить
синтаксически завершённое обрезание от полного ответа невозможно.

Отказ представлен `BrokerOutputError`, наследником `BrokerError`: существующие
fallback-ветки продолжают работать. Диагностика содержит reason, provider,
request_id, job_id и доступный finish_reason, но не текст модели, промпт,
объяснение отказа или значения полей из ошибки валидатора. Учёт уже оплаченного
вызова происходит до проверки, поэтому отклонённый ответ не исчезает из расходов.

Это исключает принятие повреждённых данных приложением, **не обещает отсутствия
ошибок генерации у провайдера**. Доступ к данным/действиям разрешается только
после этой границы и отдельной доменной проверки полномочий.

Проверка: `tests/test_broker_output.py` проводит ответы через реальный HTTP-клиент
с MockTransport, проверяет схему, причины завершения, приватность диагностики
и отсутствие скрытых повторов. Сеть и живая модель в этих тестах не используются.
